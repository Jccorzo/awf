# Phases

Every instant of a session belongs to exactly one phase, so phase times add up to the session's total. Phases come from PLAN.md; don't add one without asking. The rules that decide them live in [src/classify/default-rules.yaml](../src/classify/default-rules.yaml), and a repo can extend them in `.awf/rules.yaml`.

| Phase                  | What counts                                                                                                                                                                                                                                                                                                                |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Writing code           | Model time before an Edit or Write on a source file, plus the edit. Shell commands that write files (`mkdir`, `cp`, `mv`, `rm`, `sed -i`, output redirected to a file, `git add`/`commit` without hooks) count too                                                                                                         |
| Writing tests          | The same on test files: `*_test.go`, `*.test.ts`, `*.spec.ts`, `test_*.py`, `src/test/`, `Tests/`, `*Tests.cs` and the other patterns in the rules file                                                                                                                                                                    |
| Lint and format        | eslint, prettier, biome, ruff, black, isort, flake8, mypy, pyright, golangci-lint, gofmt, go vet, cargo clippy, cargo fmt, ktlint, detekt, swiftlint, swiftformat, dotnet format, `tsc --noEmit`, stylelint, shellcheck, rubocop                                                                                           |
| Running tests          | jest, vitest, mocha, playwright test, pytest, go test, cargo test, gradle test, mvn test, dotnet test, xcodebuild test, swift test, bazel test, bun test, `node --test`, rspec                                                                                                                                             |
| Build                  | tsc, vite build, webpack, esbuild, next build, go build, cargo build, gradle assemble, mvn package, dotnet build, msbuild, xcodebuild build, swift build, bazel build, make, cmake --build, docker build. Installing dependencies (`npm install`, `pip install`, `go mod download`, ...) counts as Build, tagged `install` |
| Rework                 | Code or test edits, and the model time before them, after a failed lint, test or build, until that same check passes                                                                                                                                                                                                       |
| Exploring              | Read, Grep, Glob, web search and fetch, and the model time before them. Shell commands that only read: `ls`, `cat`, `grep`, `rg`, `find`, `git status`/`log`/`diff`, `--version` and `--help`                                                                                                                              |
| Planning and answering | Model time that ends without a tool call, and planning tools (TodoWrite, the task list, plan mode, handing results back from a subagent)                                                                                                                                                                                   |
| Waiting on you         | Approval prompts, questions to you (AskUserQuestion) and idle time between turns                                                                                                                                                                                                                                           |
| Unclassified           | Anything no rule matches, shown as is and never guessed. Compactions are unclassified with the tag `compaction`                                                                                                                                                                                                            |

## Attribution rules

1. **Model time goes to the phase of the tool call it produced.** When one stretch of model time produced several calls (a batch), it takes the highest-ranked of their phases. Model time before a question to you, a subagent or nothing at all is Planning and answering.
2. **A compound command takes the highest-ranked phase**, in the order Build, Running tests, Lint and format, Writing tests, Writing code, Exploring. The other phases stay as tags. `npm run lint && npm test` is Running tests, tagged Lint and format. Commands that change nothing (`cd`, `echo`, `export`, `sleep`, `kill`, `true`) don't count; a command made only of them is Unclassified.
   - **A part no rule matches** ranks above Writing and Exploring, below the checks. Those commands take next to no time, so in `mkdir -p out && python3 gen.py` the unknown part most likely took it: the command is Unclassified, not Writing code. `python3 gen.py && pnpm test` is still Running tests.
   - **A filter after a pipe** (`| tail`, `| grep`, `| jq`) decides nothing unless it is a check or writes files: `pnpm test | tail` is Running tests, `some-cli | tail` is Unclassified.
   - **Polling** (a `sleep` inside a `while`/`until`/`for` loop, or a sleep of 5 seconds or more) is Unclassified, tagged `polling`, unless the command also runs a check: the time went to waiting for something awf can't see.
   - Calls of shell functions defined in the same command, and `case` patterns, are skipped; the function's body is counted once.
3. **Scripts are resolved to what they actually run before classifying**: `npm run <script>` and its `pnpm`, `yarn` and `bun` forms (with their `pre` and `post` scripts), `make <target>` (the target's own recipe; an empty one runs its prerequisites), Gradle tasks and Maven goals (by task name), and `git commit` (its pre-commit hook). When the file that defines a script can't be read, its name decides (`test`, `lint`, `build`, ...), tagged `by-name`. `clean` doesn't count next to other tasks.
4. **A failed check is detected** from the failure event or exit code, or from failure patterns in the rules file matched against the output, when the transcript has it. A pipe like `pnpm test | tail` hides the exit code; the patterns catch it. In a compound command with several checks, a tool's own pattern says which check failed; without one, the highest-ranked check is marked failed.

## Overlaps and waiting

- When several things run at once (parallel calls, subagents), each instant goes to the highest-ranked phase among the calls running then, in the order of rule 2, followed by Planning and answering, Waiting on you and Unclassified.
- Background work (a background shell or subagent) only takes an instant when nothing in the foreground is running, so a build left running while you're away counts as Build, not Waiting on you.
- A call that waited for your approval is split: the wait is Waiting on you, the run its own phase. With hooks, the run is `duration_ms`; from a transcript alone the wait's length is unknown, so the whole call counts as waiting.
- A call that reads a background task's output (TaskOutput, BashOutput) takes that task's phase.
- Only gaps between turns count as waiting: time before your first prompt and after the last turn isn't part of the session.
